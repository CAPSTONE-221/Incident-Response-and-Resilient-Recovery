# Backup & Recovery Point Trust Validation Dataset

## Objective
This dataset evaluates the core novel contribution of this project: **Trust-Conditioned Recovery Planning (TCRP)** and the **Recovery Trust Score (RTS)** mathematical formulation.

## Mathematical Formulation
$$\text{BaseTrust} = w_1 I + w_2 V + w_3 T + w_4 F$$
$$\text{RTS} = \text{BaseTrust} \times (1 - R)$$

Where:
- $I \in [0, 1]$: **Integrity Confidence** (SHA-256 hash match, filesystem consistency, restore test validation).
- $V \in [0, 1]$: **Temporal Validity / Pre-Compromise Confidence** (Timestamp distance relative to estimated initial access).
- $T \in [0, 1]$: **Threat-Free Confidence** (IOC scans, static YARA checks, Volatility memory scans, clean entropy).
- $F \in [0, 1]$: **Forensic & Provenance Confidence** (Chain of custody, immutable backup storage audit logs).
- $R \in [0, 1]$: **Reinfection & Compromise Risk** (Backup server compromise indicators, exposed credentials, active C2 links).
- Weights: $w_1 = 0.30, w_2 = 0.30, w_3 = 0.25, w_4 = 0.15$ ($\sum w_i = 1.0$).

## Decision Gates & Trust States
| RTS Value / Condition | Trust State | Autonomous Action Permitted |
|-----------------------|-------------|-----------------------------|
| $\text{RTS} \ge 0.75$ and no hard violation | **TRUSTED** | Eligible for autonomous restoration |
| $0.40 \le \text{RTS} < 0.75$ or evidence incomplete | **UNCERTAIN** | Requires human approval & isolated sandbox restore verification |
| $\text{RTS} < 0.40$ or hard security violation | **UNTRUSTED** | Hard exclusion from recovery candidates |

*Hard Rejection Rule*: Confirmed malicious binaries, tampered hashes, or known root compromise on the backup storage immediately sets the state to `UNTRUSTED` regardless of the numeric BaseTrust score.

A benchmark dataset of 500 candidate recovery points is generated by:

Outputs `synthetic_rts_benchmark.csv` containing:

- Continuous parameters ($I, V, T, F, R$), calculated RTS, policy state, and ground-truth cleanliness.
